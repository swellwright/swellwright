# Состояние проекта

Базовый срез: `phase-3-complete`, коммит `19cdee2`, 2026-11-22. Это pre-alpha с
реализацией фаз 1–3, ещё не production-релиз. Версия описания API — 0.31.0.

Реализованы консоль/API, вход/TOTP, роли и аудит, vault, runtime плагинов, инвентарь
серверов, SSH-команды и артефакты, интеграция с Remnawave на чтение, снимки/diff,
проверки соглашений, сверка, расчёт влияния, baseline и дашборд.

Общий workflow-движок, worker и policy пока каркасы. Полные deploy/rollback,
CLI, probe-agent, web-терминал и запись в панель запланированы. Текущий исполнитель
отдельных команд работает в API; его наличие не означает готовность общего движка.

Перед фазой 4: расследовать нестабильный тест потокового вывода на Linux/sshd,
проверить severity сверки при пустом инвентаре, зафиксировать политики согласований
и подготовить изолированный стенд с PostgreSQL для deploy/resume/rollback и инъекции
отказов. Повторный запуск SSH-шага объяснён и исправлен: в Ubuntu 25.10 и актуальном
`ubuntu-latest` стоят Rust-coreutils (uutils), и их `mkdir` отвечает успехом обоим из
двух конкурентов за один путь (344 из 600 и 173 из 600 тесных гонок); запуск и wrapper
использовали `mkdir` как захват, поэтому оба становились владельцами. Владелец теперь
определяется эксклюзивным созданием файла средствами shell (`set -C`), `mkdir` как замок
использовать нельзя. Тест ожидания свободного соединения в пуле SSH тоже исправлен:
`acquireTimeoutMs: 150` ограничивал и установку первого соединения — поднят до 1000мс.
Также остаются решения о `panel:console` для оператора, ограниченных SSH-ключах
администратора и политике хранения снимков.
