# Соглашения, сверка и влияние: как писать набор соглашений

Страница «Проверки» консоли (Панель > Проверки) задаёт три вопроса о подключённой панели Remnawave, и ни один из них ничего в ней не меняет:

- **Соглашения**: соответствует ли содержимое панели вашим правилам? Движок правил читает каждый хост, ноду, профиль, сквад и шаблон и перечисляет то, что нарушает правило.
- **Сверка**: согласуются ли между собой хосты, ноды и инвентарь серверов? Хост должен указывать на ноду, которая его обслуживает, у ноды должен быть сервер, имя должно разрешаться в то, что о нём говорит панель.
- **Влияние**: что сделает это изменение? Пробный прогон берёт задуманное изменение и говорит, какие ноды перезапустятся, какие хосты и подписки изменятся и что скажет проверка соглашений после него.

Ваши правила это **данные**: набор соглашений. Ничего об установке (домен, адрес, маркер, схема имён) в коде нет. Эта страница описывает формат набора, правила, язык шаблонов и смысл трёх проверок. Проект решения: [ADR 0044](../adr/0044-conventions-reconciliation-and-impact.md); набор, с которого можно начать: [`examples/conventions/convention-pack.example.yaml`](../../examples/conventions/convention-pack.example.yaml).

## Набор

Набор это документ YAML или JSON (JSON тоже YAML). В консоли **«Править набор»** открывает его в редакторе, который проверяет текст по мере набора, показывает строку синтаксической ошибки и путь неверного значения и сохраняет набор как **новую версию** с комментарием. История хранит каждую версию; **«Сбросить»** возвращает встроенный набор и не удаляет историю. То же через API: `GET`, `PUT` и `POST .../validate` на `/panel/checks/convention-pack`.

```yaml
format: swellwright.conventions/v1     # обязательно, ровно так
name: Мои соглашения                   # обязательно, 1-100 символов
description: Для чего этот набор       # необязательно

scope:                                 # необязательно: область для каждого правила без своей
  excludeTags: [TEST]
  exclude: ".*[Tt]est.*"

rules:                                 # необязательно: настройки по id правила
  host.sni-explicit:
    severity: error                    # error | warning | info
  node.name-pattern:
    params: { pattern: "[A-Z]{2}-[0-9]{2}" }
    note: Почему правило настроено так   # показывается рядом с правилом
  profile.shared:
    enabled: false                     # выключить правило

reconciliation: { ... }                # необязательно, см. ниже
impact: { ... }                        # необязательно, см. ниже
```

- **Неизвестные ключи отклоняются.** Опечатка (`severty`) это ошибка, а не настройка, которая молча ничего не делает. Неизвестный id правила это предупреждение (набор, написанный для более новой версии, всё равно загрузится).
- Правило, которого набор не называет, сохраняет значения по умолчанию. **Встроенный набор** перечисляет все правила с параметрами по умолчанию и не содержит данных установки: ни домена, ни адреса, ни маркера, ни шаблона. Правило, которому нужен шаблон (`*.name-pattern`, `host.remark-pattern`), по умолчанию его не имеет и показывается как «нужны параметры», пока набор его не задаст.
- **Не кладите в набор секреты.** Он хранится в базе как написан (с комментариями) и виден каждому, кто может читать проверки; в журнале аудита остаются только его хеш и размер, текст туда не попадает.
- Пределы: 256 КиБ текста, 200 правил, 50 тегов на область, шаблоны до 256 символов.
- Набор хранится **для места подключения к панели**: он переживает переподключение и смену токена.
- Хеш, который показывается рядом с набором (SHA-256 его канонического JSON), позволяет двум установкам сравнить наборы, не сравнивая текст.

### Область

Область говорит, какие объекты судит правило. Её можно задать на наборе (`scope`) и на правиле (`rules.<id>.scope`); своя область правила **заменяет** область набора, а не дополняет её.

| Ключ | Смысл |
|---|---|
| `tags` | только объекты хотя бы с одним из этих тегов |
| `excludeTags` | не объекты с любым из этих тегов (например, тег для тестовых объектов) |
| `match` | только объекты, имя которых (у хоста remark) целиком подходит под шаблон |
| `exclude` | не объекты, имя которых целиком подходит под шаблон |

### Шаблоны

Шаблоны в наборе **не** регулярные выражения JavaScript. Набор приходит от человека, а шаблон это программа: на движке языка шаблон вроде `(a+)+$` на короткой строке работает экспоненциально долго и останавливает сервер. Здесь шаблоны сопоставляются автоматом, который никогда не откатывается назад, так что время равно длине значения, умноженной на размер шаблона, каким бы шаблон ни был.

Шаблон всегда подходит под **значение целиком** (`^` в самом начале и `$` в самом конце допускаются и игнорируются). Поддерживается:

- литералы, `.`, экранирования `\d \D \w \W \s \S \p{...} \P{...} \uXXXX \u{...} \xHH \n \t \r` и экранированный символ
- классы `[A-Z0-9_-]` (члены, диапазоны, `^` для отрицания, те же экранирования внутри), группы `( )`, `(?: )`, именованные группы (они ничего не захватывают), чередование `|`
- квантификаторы `* + ? {n} {n,} {n,m}`, ленивые формы допускаются (для ответа «да или нет» они ничего не меняют)

`\p{...}` и `\P{...}` принимают имя из **фиксированного списка**: общая категория (`L`, `Lu`, `Ll`, `N`, `Nd`, `P`, `S`, `Z` и остальные по стандарту, короткие или длинные), двоичное свойство (`Alphabetic`, `Uppercase`, `Lowercase`, `White_Space`, `Emoji`, `Emoji_Presentation`, `Extended_Pictographic`, `Regional_Indicator`, `ASCII`, `Any` и ещё несколько) или `Script=` (также `sc=`, `Script_Extensions=`, `scx=`) с `Latin`, `Cyrillic`, `Greek`, `Han`, `Hiragana`, `Katakana`, `Hangul`, `Arabic`, `Hebrew`, `Thai`, `Devanagari`, `Armenian`, `Georgian` или `Common`. Всё остальное отклоняется с указанием позиции, чтобы было известно, о чём набор может спросить движок языка. Никакой другой текст набора до этого движка не доходит: сокращения, точку и классы решает код Swellwright, а тест сравнивает их с движком на каждом символе, где они могли бы разойтись.

Отклоняется, с номером символа: обратные ссылки, просмотр вперёд и назад, границы слов (`\b`), якорь посередине, квантификатор без операнда, счётчик больше 64, шаблон длиннее 256 символов или такой, которому нужно больше 5000 состояний автомата. Значение длиннее 512 символов не подходит ни под какой шаблон. При сохранении проверяется каждый шаблон, так что редактор говорит об ошибке до того, как что-то запустится.

## Правила

`GET /panel/checks/rules` (и таблица на вкладке «Соглашения») перечисляет все правила с параметрами, значениями по умолчанию и тем, как их задаёт действующий набор. У находки есть важность, объект, правило, текст на языке пользователя, затронутые поля как JSON Pointer в редактируемой форме объекта и, когда исправление очевидно, **подсказка** (`replace /address на ...`). Подсказка это информация: ничто её не применяет.

| Правило | Объект | По умолчанию | Что находит | Параметры |
|---|---|---|---|---|
| `host.address-policy` | хост | warning | адрес пуст или не того вида, который требует политика | `policy`: `any`, `ip`, `domain` |
| `host.sni-explicit` | хост | warning | хост без SNI | |
| `host.remark-unique` | хост | warning | пустой remark или такой, который совпадает у двух хостов | `caseSensitive` |
| `host.remark-pattern` | хост | warning | remark не подходит под шаблон | `pattern` (обязателен) |
| `host.inbound-exists` | хост | error | хост без инбаунда, с несуществующим профилем или инбаундом либо с инбаундом другого профиля | |
| `host.serving-node` | хост | warning | инбаунд хоста не обслуживает ни одна нода, либо назначенной ноды нет или она его не обслуживает | |
| `host.state` | хост | info | хост выключен или скрыт | `report` |
| `host.sni-in-inbound-names` | хост | warning | SNI, которого нет среди server names его REALITY-инбаунда | |
| `host.vless-route-id` | хост | warning | `vlessRouteId` зарезервирован, вне диапазона или (по желанию) общий | `reserved`, `max`, `warnOnDuplicates` |
| `node.has-host` | нода | warning | нода, на которую не указывает ни один хост | |
| `node.disabled-referenced` | нода | warning | выключенная нода, которая последний сервер инбаунда или всё ещё назначена хосту | |
| `node.version-skew` | нода | warning | версия node или Xray отличается от остальных либо панель другой линии выпусков | `checkNodeVersion`, `checkXrayVersion`, `sameLineAsPanel` |
| `node.address-valid` | нода | error | адрес не IP и не доменное имя | |
| `node.profile-assigned` | нода | warning | нет профиля, профиль не существует или нет активных инбаундов | |
| `node.plugin-exists` | нода | error | нода использует плагин, которого нет в панели | |
| `node.name-pattern` | нода | warning | имя не подходит под шаблон | `pattern` (обязателен) |
| `profile.inbound-tag-unique` | профиль | error | тег инбаунда использован дважды, в одном профиле или в разных (теги в панели глобальные) | |
| `profile.inbound-port-clash` | профиль | error | два инбаунда одного профиля на одном порту | |
| `profile.snippet-exists` | профиль | error | конфигурация использует сниппет, которого нет в панели | |
| `profile.name-pattern` | профиль | warning | имя не подходит под шаблон | `pattern` (обязателен) |
| `profile.unused` | профиль | info | профиль, которым не пользуется ни одна нода, или без инбаундов | |
| `profile.shared` | профиль | info | профиль, которым пользуются не меньше `minNodes` нод (правка одного инбаунда перезапустит их все) | `minNodes` |
| `squad.internal-empty` | внутренний сквад | warning | сквад без инбаундов или без участников | |
| `squad.inbound-exists` | внутренний сквад | error | сквад перечисляет инбаунд, которого нет в панели | |
| `squad.name-pattern` | сквад | warning | имя не подходит под шаблон | `pattern` (обязателен), `kinds` |
| `squad.external-template-exists` | внешний сквад | error | сквад указывает на отсутствующий шаблон или шаблон не того типа | |
| `template.name-pattern` | шаблон | warning | имя не подходит под шаблон | `pattern` (обязателен) |
| `template.body-present` | шаблон | error | тело шаблона не читается | `types` |
| `template.unused` | шаблон | info | шаблон, которым не пользуется ни один внешний сквад и ни один хост | |
| `panel.token-expiry` | панель | warning | токен, которым пользуется Swellwright, истекает в течение `warnDays` дней или уже истёк | `warnDays` |

Правилу нужны некоторые виды объектов (`needs`). Если токен подключения не может прочитать один из них, правило **пропускается и попадает в список пропущенных** с указанием, чего ему не хватило; остальной прогон это не затрагивает. Правило, которое упало, изолируется и попадает в список сбойных, остальные правила работают. Прогон выдаёт не больше 5000 находок и сообщает, если его обрезали.

### Находки о панели, а не о секретах

Проверки читают панель через маскированные представления: приватный ключ, short id или адрес подписки никогда не попадают ни в правило, ни в находку, ни в журнал аудита, ни в строку журнала. Находка о секрете говорит только, что он есть или что он изменился.

## Сверка

`GET /panel/checks/reconciliation` (`?refresh=true` заново спрашивает панель и забывает память DNS) сравнивает хосты, ноды и **инвентарь серверов** Swellwright и ищет имена в DNS. Она возвращает строки; у строки есть **статус**:

| Статус | Смысл |
|---|---|
| `ok` | как ожидалось |
| `drift` | стороны расходятся (хост указывает на адрес, который не адрес ноды) |
| `missing` | у другой стороны нет пары (нода, которой нет в инвентаре, имя без записи) |
| `extra` | в инвентаре есть то, чего нет в панели (сервер без ноды; выведенные из работы серверы не показываются никогда) |
| `unknown` | решить не удалось: имя не разрешилось вовремя или инбаунд хоста никто не обслуживает. Это строка, а не ошибка всего отчёта |

Проверки, каждую из которых набор может выключить (`reconciliation.checks.<id>.enabled: false`):

| Проверка | Что сравнивает |
|---|---|
| `host.address` | адрес хоста с нодой, которая его обслуживает |
| `host.sni` | SNI хоста с адресом ноды |
| `host.port` | порт хоста с портом его инбаунда |
| `host.node` | назначенные хосту ноды существуют и обслуживают его инбаунд |
| `host.duplicate` | два хоста с одним адресом, портом и SNI для одного инбаунда |
| `node.dns` | имя ноды разрешается (в IP, с TTL, который допускает набор) |
| `node.disabled-resolving` | выключенная нода, имя которой всё ещё разрешается |
| `node.duplicate` | две ноды с одним адресом |
| `node.server` | у ноды есть сервер в инвентаре (по адресу, по DNS или по имени хоста из фактов) |
| `server.node` | у сервера инвентаря есть нода |
| `server.duplicate` | два сервера с одним адресом |

Настройки в наборе:

```yaml
reconciliation:
  hostAddress: node          # node (по умолчанию) | node-ip | node-address | none
  hostSni: none              # none (по умолчанию) | node-address
  hostPort: none             # none (по умолчанию) | inbound
  dns:
    enabled: true
    maxTtlSeconds: 3600      # запись с большим TTL показывается с подсказкой
  inventory:
    matchBy: [address, dns, hostname]
    reportUnmanaged: true
    reportExtra: true
  checks: { server.duplicate: { enabled: false } }
  scope: { excludeTags: [TEST] }
```

`hostAddress`: `node` принимает адрес ноды, IP ноды или имя, которое разрешается в IP ноды; `node-ip` требует IP ноды; `node-address` требует ровно тот адрес, что у ноды в панели; `none` не проверяет.

**DNS опрашивается в пределах.** Один запрос на каждое различное имя за прогон, тайм-аут одного запроса, потолок числа имён за прогон, ограниченная параллельность, предел цепочки CNAME, короткая память ответов и ограничение частоты на пользователя для всего отчёта. Имена разрешает машина, на которой работает Swellwright, или серверы из `SW_CHECKS_DNS_SERVERS`. Ответ с адресом, к которому слой SSH отказался бы подключаться (loopback, link-local, частные и так далее, если установка их не разрешила), показывается как «разрешается в запрещённый адрес» и не используется. Имя, которое не опрошено из-за потолка, получает `unknown` с причиной `dns_skipped_cap`, и отчёт говорит, сколько таких.

Сверка **только проверяет**. Исправление в строке это подсказка о том, что сделала бы последующая, подтверждённая запись; здесь ничто не пишет ни в панель, ни в DNS, ни в инвентарь. Записи в журнал аудита сверка тоже не делает, потому что ничего не меняет.

## Влияние: пробный прогон

`POST /panel/impact` принимает вид (`configProfile`, `internalSquad`, `host`, `node`, `subscriptionTemplate`), `uuid` объекта и **изменение**: либо объект с полями, которые меняются (пропущенные поля остаются как есть), либо **JSON Patch** (RFC 6902) к редактируемой форме объекта. `GET /panel/impact/target` отдаёт эту форму (секреты замаскированы), с неё начинает редактор консоли. В ответе:

- **перезапуски**: какие ноды перезапустятся, остановятся или запустятся, у каждой правило, которое так говорит;
- **применённые правила**, каждое с пометкой **наблюдалось** (видели на настоящей панели), **документировано** (так сказано в документации панели) или **предположение** (выведено, не видели), чтобы было понятно, насколько ему верить;
- **уровень риска** (`low`, `medium`, `high`) с причинами;
- **пользователи** онлайн на нодах, которые перезапустятся (число, которое сообщает панель, а не обещание);
- **хосты и подписки**, которые изменятся, **висячие ссылки**, которые изменение оставит, хосты без обслуживающей ноды;
- что скажет проверка соглашений о результате: находки, которые изменение **вносит**, и находки, которые оно **исправляет**;
- **более безопасный способ**, если он есть (для общего профиля: клонировать профиль под ноду, которой нужна правка);
- **примечания**: поля, которые отброшены как не входящие в форму, конфигурация, которую не удалось прочитать, панель другой линии выпусков, чем та, для которой написана таблица, изменённый секрет.

Это чистое вычисление над тем, что панель сообщила в последний раз: оно не отправляет изменение в панель, не пишет в журнал аудита и никогда не повторяет значение предложения в ответе.

Таблица правил (версия `3.4`, для Remnawave 3.4.x):

| Правило | Эффект | Основание |
|---|---|---|
| `profile.config-edit` | правка конфигурации профиля перезапускает Xray на **каждой ноде профиля**, даже если изменён один инбаунд | наблюдалось |
| `profile.name-only` | переименование профиля или смена тегов ничего не перезапускает | предположение |
| `squad.inbounds-changed` | смена инбаундов внутреннего сквада перезапускает ноды, обслуживающие добавленные или убранные инбаунды | наблюдалось |
| `squad.members-changed` | добавление или удаление участников не перезапускает ни одну ноду | предположение |
| `squad.metadata-only` | переименование сквада или смена тегов ничего не перезапускает | предположение |
| `node.profile-move` | перенос ноды в другой профиль перезапускает только эту ноду | документировано |
| `node.active-inbounds-changed` | смена активных инбаундов ноды перезапускает только эту ноду | документировано |
| `node.disable` | выключение ноды останавливает её и отключает её пользователей | документировано |
| `node.enable` | включение ноды запускает её | предположение |
| `node.connection-changed` | смена адреса или порта заставляет панель подключиться заново, что перезапускает Xray на этой ноде | предположение |
| `node.metadata-only` | имя, теги, заметка и подобное ничего не перезапускают | предположение |
| `host.edit` | правка хоста не перезапускает ни одну ноду; подписки, куда хост входит, меняются | документировано |
| `template.edit` | правка шаблона подписки не перезапускает ни одну ноду; подписки, которые его используют, меняются | документировано |

Если панель другой линии выпусков, чем таблица, ответ об этом говорит; числа тогда оценка.

```yaml
impact:
  highRiskRestartNodes: 3    # изменение, перезапускающее не меньше стольких нод, высокого риска
  highRiskRestartShare: 0.5  # или не меньше такой доли работающих нод
```

Уровень это наибольший из поводов, и каждый повод перечисляется рядом. **Высокий**: перезапуски не меньше любого из пределов, ссылки, которые указывали бы на несуществующий инбаунд, хосты без обслуживающей ноды, изменение вносит ошибку соглашений. **Средний**: перезапускается какая-то нода, профиль общий для нескольких нод, на перезапускаемых нодах есть пользователи онлайн, изменение вносит предупреждения, изменение заменяет замаскированный секрет. **Низкий**: ничего не перезапускается и больше ничего не плохо.

## Кто что может

| Действие | Нужно |
|---|---|
| запускать соглашения и сверку, перечислять правила, читать набор и его историю, считать влияние | `panel:read` |
| сохранить или сбросить набор | `panel:write` и повышенная аутентификация (код аутентификатора) |
| загрузить набор из файла | как сохранение: консоль кладёт файл в редактор, а сохранение это `PUT` |
| выгрузить набор (YAML или JSON) | `panel:read`: это `GET` набора |

`POST .../validate` требует только `panel:read`: он проверяет набор и ничего не сохраняет. API-токен может то, что позволяют его права и роль владельца, кроме маршрутов с повышенной аутентификацией. Сверка сравнивает инвентарь серверов только тогда, когда вызывающий вправе его читать; иначе она сообщает, что инвентарь не сравнивался.

Каждое изменение набора это событие аудита в той же транзакции, что и изменение: `panel.convention_pack.saved` (версия, хеш, имя, число правил, источник текста, заменил ли он версию; никогда не документ и не текст) и `panel.convention_pack.reset`. Сохранение, которое ничего не меняет (тот же набор, пусть и с другими пробелами), новой версии не создаёт.

## Настройки сервера

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `SW_CHECKS_DNS_TIMEOUT_SECONDS` | `3` | тайм-аут одного запроса DNS (0,2-30) |
| `SW_CHECKS_DNS_MAX_NAMES` | `200` | сколько имён опрашивается за прогон (1-2000) |
| `SW_CHECKS_DNS_CONCURRENCY` | `8` | запросов одновременно (1-32) |
| `SW_CHECKS_DNS_CACHE_SECONDS` | `60` | сколько помнится ответ (0-3600; 0 не помнит ничего) |
| `SW_CHECKS_DNS_SERVERS` | пусто | IP резолверов через запятую (`IP` или `IP:порт`); пусто означает системный резолвер |
| `SW_CHECKS_RATE_LIMIT_PER_MINUTE` | `12` | прогонов сверки на пользователя в минуту (1-600); `refresh=true` ещё учитывается в `SW_PANEL_REFRESH_RATE_LIMIT_PER_MINUTE` |
