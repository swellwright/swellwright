# 10. Тестирование и качество

> Документ описывает целевую стратегию тестирования. Действующие команды и ограничения проверок — в [development.md](../development.md); существующие TypeScript-тесты используют `node:test`.

Без чистой лаборатории откат и развёртывание проверять негде: типичные сбои установки (блокировка менеджера пакетов, недоступность репозитория) проявляются только при запуске на настоящем сервере. Лаборатория и инъекция сбоев часть плана, а не «потом».

## 1. Пирамида тестов
| Уровень | Что | Инструменты |
|---|---|---|
| Модульные | чистые функции, политики, калькулятор влияния, шаги с фейками | Vitest |
| Контрактные | клиент панели против замороженной спеки; Swellwright API против своей спеки | `oasdiff`, Schemathesis, Prism |
| Интеграционные | api, воркер, очереди, БД | Testcontainers (Postgres, Valkey) |
| Движок | сценарии на фейковых панели и SSH (сквозные сценарные тесты поведения, «золотые») | собственный стенд |
| Системные (E2E) | сценарии в лаборатории: настоящая панель в контейнерах и настоящие VM-ноды | Docker Compose + VM |
| UI | формы, потоки, визуальные регрессии, доступность | Playwright, axe |
| Безопасность | авторизация, утечки секретов, XSS/CSRF/SSRF, инъекции в вывод | собственные проверки, ZAP, gitleaks |
| Нагрузка (малая) | десятки одновременных запусков и логов | k6 |
| Обновления | миграции вперёд и назад, резервные копии | сценарные тесты |

## 2. Фейки и стенды
- **Фейковая панель:** stateful-сервер по OpenAPI (модель в памяти: узлы, хосты, профили, сквады), включая поведение «рестарт всех нод общего профиля» для проверки калькулятора влияния.
- **Реальная панель в лаборатории:** образ `remnawave/backend` версии 3.4.x с Postgres и Valkey в Docker; ноды подключаются настоящие (`remnawave/node` в VM). Матрица версий панели (текущая и предыдущая минорная).
- **Фейковый SSH-сервер** на `ssh2` с сценарными ответами (для тестов на разрыв, медленные команды, коды возврата) и **настоящие контейнеры/VM** Ubuntu 22.04 и 24.04 (systemd, apt, ufw, Docker внутри VM).
- **Фейковые DNS-провайдеры:** HTTP-сервер, имитирующий API RU-CENTER (NIC.RU), UDP-DNS для проверки авторитативных ответов.

## 3. Лаборатория
- Платформа: Multipass, QEMU/KVM, Hyper-V или иная платформа виртуализации (на выбор), 4-6 VM: 2x Ubuntu 24.04, 2x 22.04, 1 «хост панели», 1 «хост Swellwright»; снимки VM для быстрого возврата.
- Сеть: изолированная; управляемый DNS (dnsmasq/CoreDNS) со своей зоной; фейковые «внешние адреса».
- Сценарии лаборатории: развёртывание, переразвёртывание, переименование, откат, обновления образа, перезагрузки, смена ACL, терминал.
- **Эквивалентность отката:** после отката манифест файлов, списки пакетов, пользователей и правил должны совпасть со снимком до запуска (исключения перечислены); тест автоматически сравнивает.

## 4. Каталог инъекции сбоев
Обрыв SSH посреди шага; перезагрузка сервера посреди запуска; убийство воркера (подхват другим); блокировка менеджера пакетов другим процессом (например `unattended-upgrades`); недоступность репозитория или его ключа; медленный DNS и кэш резолвера; ответы 5xx и таймауты панели; истёкший токен панели и DNS; пустой или повреждённый ответ; переполнение диска; рассинхрон времени; несовпадение SECRET_KEY; сбой cert-sync; потеря входа после правки UFW (проверка таймера страховки); одновременные запуски на один ресурс (блокировки); изменение объекта в панели между чтением и записью; смена ключа хоста SSH; потеря связи между воркером и БД; переполнение логов.

## 5. Критерии приёмки по сценариям (образцы Given/When/Then)
- **Развёртывание:** Given чистая Ubuntu 24.04 и панель с образцом профиля, When запуск N03, Then нода online, хосты и сквады созданы, `verify` без ошибок, доступ Swellwright работает, root закрыт, повторный запуск ничего не меняет.
- **Откат развёртывания:** Given неудачное N03 на шаге `nginx`, When откат, Then панель очищена, DNS возвращён, сервер совпадает со снимком (кроме перечисленных исключений).
- **Переименование:** Given нода с двумя хостами и хоп-профилем со ссылкой, When N05 в безопасном режиме, Then оба имени работают, ссылки обновлены по выбору, `finalize` убирает старое имя, откат возвращает всё.
- **Возобновление:** Given убитый воркер на 7-м шаге, When запуск подхвачен, Then шаг дочитан по журналу на ноде и запуск продолжен без дублирования.
- **Политики:** Given правка общего профиля, привязанного к нескольким нодам, When план, Then показан список нод и время, требуется согласование.
- **Секреты:** Given запуск с любым исходом, Then в журналах, событиях, ответах API и резервных копиях нет значений секретов (автоматический поиск).

## 6. Качественные ворота (CI или локальный скрипт)
`tsc --noEmit` (strict), ESLint, формат, модульные и контрактные тесты (покрытие движка и политик не ниже 85%), Spectral и `oasdiff`, gitleaks, `pnpm audit`, SBOM, проверка лицензий, размер бандла, axe; без прохождения релиз не выпускается.

## 7. Тестовые данные
Анонимизированные экспорты реальной панели (замена доменов, IP, ключей), генераторы синтетических парков разного размера, сценарные профили зондов.

## 8. Определение готовности (DoD) для функции
Код, тесты (включая негативные и сбойные), обновлённая OpenAPI и SDK, документация и примеры, запись в каталоге сценариев, политика и права описаны, метрики и аудит подключены, проверка в лаборатории с отметкой «проверено в лаборатории» там, где применимо.

## 9. Чек-лист первых запусков в лаборатории
Сначала чтение (усыновление, аудит), затем тестовое имя DNS (создать и откатить), затем переразвёртывание и переименование тестовой ноды, затем ноды с трафиком вне часов пик, если администратор решит; после каждого шага сравнить состояние и журнал.

## 10. Лаборатория на реальном сервере (рекомендации)
- **Роль сервера:** отдельный настоящий VPS для полных циклов N03, N04, N05, N06, N07, N11 с настоящими `apt`, `ufw`, Docker, перезагрузкой; между циклами ОС переустанавливается (в панели хостера или через API провайдера).
- **Панель:** отдельная тестовая панель с объектами, помеченными тегом `sw-lab`: узел `XX-99`, тестовый профиль, тестовый сквад, хосты с пометкой 🧪. Страхует политика **P-016 «режим лаборатории»**: запуск может менять только объекты с тегом `sw-lab`, всё остальное блокируется; массовые операции и операции над общими профилями в этом режиме запрещены. Перед каждым прогоном автоматически делается снимок панели.
- **Доступ к серверу:** IP, root и пароль администратор вводит в момент проверки (в репозиторий и конфигурацию не попадают); перед рискованными проверками иметь доступ к консоли хостера.
- **Что проверять там:** полный цикл «развёртывание, откат, повтор»; блокировка менеджера пакетов (запуск `unattended-upgrades`); обрыв SSH правилом `iptables`; перезагрузка посреди запуска; таймер страховки при потере входа после UFW; переименование и финализация; медленный DNS; плагины-сайдкары.
- **Ограничение:** этот сервер недоступен публичному CI (секреты); для публичных проверок используются фейки и контейнеры (разделы 2-3).
