# 09. Docker, размещение, эксплуатация

## 1. Состав контейнеров (как у панели: приложение, PostgreSQL, Redis-совместимое хранилище)
| Сервис | Образ | Роль | Сеть |
|---|---|---|---|
| `swellwright` | свой (multi-stage, non-root; API и интерфейс в одном) | api + раздача интерфейса | внутренняя + публикация только на 127.0.0.1 за nginx |
| `migrate` | тот же образ, другая команда | один раз применяет миграции базы перед запуском сервера | только внутренняя |
| `swellwright-worker` | тот же образ, другая команда (планируется; первый срез движка работает в процессе API, ADR 0048) | выполнение сценариев, SSH, зонды | внутренняя + исходящие по allowlist |
| `postgres` | `postgres:17` (закреплён по дайджесту) | БД | только внутренняя |
| `valkey` | `valkey/valkey:8` (закреплён по дайджесту) | проверка готовности; позже лимиты и пробуждение (запуски и блокировки в PostgreSQL, ADR 0048) | только внутренняя |
| `swellwright-probe` | свой, отдельный образ (планируется, опц.) | агент зонда на машинах-наблюдателях | наружу только HTTPS к api |

Образ собирает `Dockerfile` в корне репозитория с `pnpm install --frozen-lockfile --ignore-scripts`; базовый образ, pnpm и движок Prisma закреплены и проверяются (ADR 0019). Релизные образы тегируются версией (`swellwright:1.0.0`), без `latest`; их собирает и публикует CI (раздел 10). До этого образ собирается из рабочей копии compose-файлом.

## 2. `docker-compose.yml`
Файл лежит в `deploy/compose/docker-compose.yml`; секреты пишутся в `.env` рядом (каждый объяснён в `.env.example`), затем `docker compose up -d --build` (ADR 0019). Что он задаёт:
- `migrate` выполняет `prisma migrate deploy` и завершается; `swellwright` стартует после его успешного завершения и после готовности Postgres и Valkey.
- `swellwright`: непривилегированный пользователь, `read_only: true` с `/tmp` в памяти, `cap_drop: [ALL]`, `no-new-privileges`, `init`, публикация на `127.0.0.1:3100` (`SW_LISTEN`), `SW_TRUSTED_PROXIES=uniquelocal`, потому что прокси приходит к нему из сети Docker.
- Сети: `backend` с `internal: true` (Postgres, Valkey, `migrate`, сервер); `frontend` несёт опубликованный порт и исходящий трафик сервера.
- Обязательные секреты (`POSTGRES_PASSWORD`, `SW_AUTH_KEY`) проверяет Compose; без них запуск останавливается с сообщением.
- Планируется и пока не в файле: worker, Docker secrets для пароля базы, лимиты ресурсов.

Исходящий трафик ограничивается межсетевым экраном хоста (разрешены серверы инвентаря, панель, DNS-API, GitHub, Telegram), а не только Docker.

## 3. Переменные окружения (основные)
`SW_PUBLIC_URL`, `SW_VERSION`, `SW_DATABASE_URL`, `SW_VALKEY_URL`, `SW_AUTH_KEY` (base64 от 32 случайных байт; запечатывает секреты TOTP, это не ключ хранилища, ADR 0014; обязателен в production), `SW_SETUP_TOKEN` (необязательный постоянный токен первого запуска), `SW_COOKIE_SECURE`, `SW_ALLOWED_ORIGINS`, `SW_STEP_UP_MINUTES` (сколько сессия остаётся повышенной после второго фактора, по умолчанию 5, от 1 до 30; ADR 0017), `SW_VAULT_KDF_MEMORY_MIB` и `SW_VAULT_KDF_PASSES` (стоимость Argon2id для новой фразы хранилища, по умолчанию 256 МиБ и 3; ADR 0018), `SW_LOG_LEVEL`, `SW_EGRESS_ALLOWLIST` (подсказка политике), `SW_UNSEAL_MODE` (`manual` по умолчанию, `file`, `systemd-creds`), `SW_METRICS_BASIC_AUTH` (для Prometheus), `SW_RETENTION_*`. Ещё: `SW_WEB_DIR` (каталог с собранным интерфейсом; API отдаёт его по `/`, в образе это `/app/web`, без `index.html` сервер не запускается), `SW_PLUGINS_OFFICIAL_DIR` и `SW_PLUGINS_LOCAL_DIR` (каталоги, подкаталоги которых это плагины, доверие `official` и `local`; ни один не задан: плагинов нет; ADR 0027), `SW_PLUGINS_COMMUNITY_DIR` (плагины от других, доверие `community`; только спутники и драйверы), `SW_PLUGIN_CORE_URL` (как спутник достаёт до Swellwright, `http://swellwright:3000`), `SW_PLUGIN_SIDECAR_URL` (как ядро достаёт до спутника, `http://plugin-{id}:{port}`), `SW_PLUGIN_NETWORK` (сеть compose для спутников, `plugins`) и `SW_PLUGIN_CORE_SERVICE` (служба compose Swellwright, `swellwright`; ADR 0031), `SW_PLUGIN_MEMORY_MIB` (предел кучи процесса плагина, по умолчанию 128), `SW_PLUGIN_CALL_TIMEOUT_SECONDS` (10) и `SW_PLUGIN_IDLE_MINUTES` (10; ADR 0028), `SW_SSH_ALLOW_LOOPBACK` (false), `SW_SSH_ALLOW_PRIVATE` (true) и `SW_SSH_ALLOW_HOSTNAMES` (true) (на какие адреса Swellwright вправе подключаться; link-local и адреса метаданных облака никогда), `SW_SSH_CONNECT_TIMEOUT_SECONDS` (15), `SW_SSH_COMMAND_TIMEOUT_SECONDS` (60) и `SW_SSH_RATE_LIMIT_PER_MINUTE` (20) (ADR 0037), `SW_COMMAND_CONCURRENCY` (5 серверов одного запуска одновременно), `SW_COMMAND_OUTPUT_LIMIT_KIB` (1024 на поток и сервер), `SW_COMMAND_POLL_MS` (1000), `SW_COMMAND_LOST_AFTER_MINUTES` (30) и `SW_COMMAND_RATE_LIMIT_PER_MINUTE` (10 запусков на пользователя) (ADR 0038), `SW_ENGINE_ENABLED` (true; false не запускает цикл запусков в этом процессе), `SW_ENGINE_CONCURRENCY` (от 1 до 4 запусков одновременно), `SW_ENGINE_POLL_MS` (1000), `SW_ENGINE_RENEW_MS` (10000; lease втрое длиннее), `SW_ENGINE_WAIT_BACKOFF_MS` (15000; запуск, который ждёт блокировку или запечатанное хранилище, пробуют снова через это время, а после каждого ожидания хранилища вдвое дольше, до восьми раз) и `SW_ENGINE_STOP_TIMEOUT_MS` (8000; сколько закрытие ждёт шаг, который не сдаётся) (ADR 0048) и `SW_TRUSTED_PROXIES` (какие прокси вправе сообщать адрес клиента через `X-Forwarded-For`: число переходов либо адреса, диапазоны CIDR и `loopback`, `linklocal`, `uniquelocal`; не задано: не доверяет никому; опечатка отвергается при запуске; ADR 0019). Проверка обновлений: `SW_UPDATE_CHECK` (по умолчанию `on`, `off` выключает), `SW_REPOSITORY` (`owner/name` репозитория на GitHub, по умолчанию `swellwright/swellwright`, форк задаёт свой) и `SW_UPDATE_API_BASE` (API GitHub, `https://api.github.com`; только для тестов, https или http на этой же машине). Что сборка образа записала о себе, передаётся аргументами сборки и читается из `SW_BUILD_TIME`, `SW_BUILD_NUMBER`, `SW_GIT_BRANCH` и `SW_GIT_COMMIT` (все необязательные; «Информация о сборке» в консоли показывает то, что есть). **Мастер-пароль хранилища не передаётся через окружение.**

## 4. Обратный прокси (nginx, по образцу панели)
- Домен `sw.<база>`, сертификат (например wildcard на базовый домен), `proxy_pass http://127.0.0.1:3100`. API отдаёт интерфейс сам, так что апстрим один; TLS и ограничение доступа остаются за прокси.
- Заголовки: `X-Forwarded-For`, `X-Forwarded-Proto: https`, без под-пути.
- WebSocket: `Upgrade`/`Connection`, `proxy_read_timeout` не менее 1 часа для терминала.
- Ограничение доступа: список адресов (доверенные сети, VPN), опционально mTLS; rate limiting; отдельные `location` для `/ws`.
- Закрытые `/metrics` и `/docs` для внешних адресов.
- У консоли настоящие адреса (например `/dashboard/security/users`). Прокси передаёт API любой путь, а API на GET или HEAD пути, который не лежит под `/api`, не имеет расширения в последнем сегменте и приходит от клиента, принимающего HTML, отвечает тем же `index.html` (без кеширования, с политикой безопасности содержимого консоли): прямая ссылка и перезагрузка открывают страницу. Неизвестные пути `/api/...` остаются JSON-ответом 404, как и отсутствующий файл (`/assets/missing.js`, `/favicon.svg`).

## 5. Размещение (на одном хосте с панелью или на отдельном)
Рекомендуется отдельный сервер; размещение на хосте панели допустимо с мерами изоляции: отдельный системный пользователь без sudo; отдельная docker-сеть и **свои** Postgres и Valkey (не панельные); нет доступа к `docker.sock` и к томам и сети панели; лимиты (`cpus`, `memory`, `pids`) и `read_only`; межсетевой экран с ограничением исходящих соединений контейнеров Swellwright; отдельный vhost и отдельные резервные копии; Swellwright не читает базу панели (только API); хост панели в инвентаре Swellwright как обычный сервер с ограниченным пользователем.
Ресурсы: перед запуском измерить запас CPU и RAM; базовая потребность Swellwright 2 vCPU и 2 ГБ RAM (рост от зондов и журналов).
Остаточный риск при общем хосте: общее ядро и хост; компрометация хоста затрагивает обе системы.

## 6. Первый запуск
`cp .env.example .env`, заполнить три секрета, `docker compose up -d --build` (`deploy/compose`) → открыть консоль и ввести токен установки, который сервер напечатал в журнал → создать владельца экземпляра (пароль, TOTP, коды восстановления) → создать и **распечатать** хранилище (пароль + файл ключа по желанию) → подключить панель (P01) → импортировать парк → усыновить ноды (N01) → настроить уведомления и расписания.

## 7. Эксплуатация
- **Обновления Swellwright:** новая версия образа → сервис `migrate` выполняется при `docker compose up` перед сервером → проверка `ready` → откат: предыдущий образ плюс восстановление базы из копии перед миграцией (автоматическая копия перед обновлением).
- **Резервные копии:** ежедневный `pg_dump` (шифрование в формате CMS: открытый ключ на сервере, приватный ключ хранится вне сервера у администратора), экспорт метаданных хранилища (шифртекст), копии вне сервера (внешнее хранилище), ежемесячная проверка восстановления в одноразовом Postgres.
- **Мониторинг:** `/health`, `/ready`, `/metrics` (Basic Auth), алерты на возраст блокировок, очередь, сроки токенов и сертификатов, размер БД.
- **Логи:** JSON, ротация Docker (`max-size`, `max-file`), хранение по политике, без секретов.
- **Проверка обновлений:** для кнопки версии и ссылки на проект в консоли сервер спрашивает у `api.github.com` последний выпуск и число звёзд репозитория (`GET /repos/<repository>/releases/latest` и `GET /repos/<repository>`), не чаще раза в сутки (раз в час после неудачи), хранит ответ в памяти и при запуске GitHub не вызывает. Это простой GET с `Accept`, `User-Agent: swellwright/<версия>` и `X-GitHub-Api-Version`; в нём нет ничего, что опознаёт установку, пользователя или браузер, а сам браузер GitHub не вызывает. Консоль читает результат из `GET /api/v1/updates` (любой вошедший пользователь; в журнал аудита ничего не пишется). `SW_UPDATE_CHECK=off` выключает проверку: ни один запрос не уходит, консоль не показывает сведений об обновлении. Чтобы проверка работала, GitHub должен быть в списке разрешённого исходящего трафика.
- **Часы:** NTP обязателен (сертификаты SSH и подписи вебхуков зависят от времени).

## 8. Аварийное восстановление (runbooks)
| Ситуация | Действия |
|---|---|
| Потерян пароль хранилища | распечатать ключом восстановления, показанным при настройке (консоль предлагает его под полем фразы); доли ключа (Shamir) придут позже; без ключа хранилище утрачено: перевыпуск всех секретов и повторное подключение панели и серверов (ноды живы, доступ по аварийному ключу) |
| Никто не может войти (владелец потерял пароль и аутентификатор) | на хосте Swellwright, с окружением сервера: `docker compose exec swellwright node apps/api/dist/admin.js reset-credentials <логин>` удаляет учётные данные этой записи, завершает её сессии и печатает одноразовое приглашение; открыть консоль с ним, выбрать пароль, заново подключить аутентификатор. `... admin.js users` показывает учётные записи. В цепочке аудита это `user.credentials.reset` с `via: cli` (ADR 0016) |
| Потерян сервер Swellwright | поднять на новой машине, восстановить БД из копии, распечатать хранилище, пересоздать токены агентов, проверить доступы |
| Повреждена БД | восстановление из последней копии, пересинхронизация панели и серверов, пометка запусков «неопределённое состояние» и сверка по снимкам |
| Swellwright скомпрометирован | отзыв токенов панели, смена CA SSH и ключей, смена DNS-секретов, аудит, перевыпуск (мастер N28) |
| Недоступна панель | запуски, зависящие от панели, ставятся на паузу; работа с серверами по SSH продолжается; сценарии «панель потом» |

## 9. Чек-лист усиления хоста
Обновления ОС, SSH по сертификату, UFW (разрешить 22 с доверенных, 443 с разрешённых), fail2ban, отключённый swap или шифрование, шифрование диска, отдельный пользователь, мониторинг целостности, закрытые порты БД и очереди, запрет на docker.sock в контейнерах, регулярные пересборки образов.

## 10. Выпуск проекта на GitHub
Сборка образов в GitHub Actions (multi-arch при необходимости), публикация в GHCR, теги по версии, закрепление по дайджесту, SBOM (CycloneDX), подписи cosign, проверки (линтеры, типы, тесты, gitleaks, Trivy, лицензии, `oasdiff`, проверка отсутствия данных экземпляров), релизные заметки из CHANGELOG, публикация OpenAPI как артефакта. Для установки в собственной инфраструктуре допустима и локальная сборка. Подробности в `13-plugins-and-opensource.md`.

## 11. Артефакты для узла
То, что Swellwright запускает на ноде, это файл из `artifacts/<имя>/` репозитория: `install.sh`, `manifest.json` (имя, семантическая версия, SHA-256, размер, шаги с `readOnly`, `needsRoot`, `inFull`, `params`, `requires` и параметры с шаблоном или значениями, значением по умолчанию, `secret`), README и тесты (ADR 0036). Манифест строится из скрипта командой `scripts/artifact-manifest.mjs` и проверяется в CI. Хеш сверяется до загрузки (с байтами, которые держит Swellwright) и после неё (`sha256sum` на ноде, с манифестом); при расхождении ничего не запускается. Выпущенная версия не правится. Установщик вызывается как `sh install.sh [действие]`, параметры берёт из окружения или `--env-file`, без терминала нужен `--non-interactive`, журнал `/var/log/swellwright-node-installer.log`; `preflight` и `verify` ничего не меняют и завершаются кодом 2 при сбое проверки. Его можно запустить вручную по README артефакта: так он и проверяется, пока сервер не умеет его доставлять.

**Сделано в фазе 2 (ADR 0039):** API отдаёт каталог (`GET /artifacts`, `GET /artifacts/{name}`, `.../versions/{version}` и сам файл с `Content-Disposition` и `X-Content-SHA256`) из `artifacts/` образа (`SW_ARTIFACTS_DIR` переносит каталог) и сверяет каждый файл с его манифестом (строгая схема, обычный файл внутри своего каталога, размер, SHA-256) при запуске сервера и ещё раз при каждом использовании: файл, не совпадающий с манифестом, получает состояние `broken` (виден в списке с причиной, записан в цепочку аудита, не отдаётся и не отправляется) и не мешает серверу запуститься. `node apps/api/dist/admin.js artifacts` делает ту же проверку снаружи, и её запускает задача `image` в CI. `POST /servers/{id}/artifacts` считает хеш файла, загружает его по SFTP под временным именем, просит сервер посчитать хеш (`sha256sum`), переименовывает на место только при совпадении, выставляет права (0755 для скрипта, 0644 для файла данных) и просит сервер посчитать хеш ещё раз; при сбое на месте файла ничего не остаётся, а оборванную отправку подчищает следующая. Место по умолчанию: `~/.swellwright/artifacts/<name>/<version>/<file>` пользователя, под которым вошли (доступно только ему); `destination: system` это `/var/lib/swellwright/artifacts/...` с владельцем root, запись через sudo-путь слоя SSH. `POST /servers/{id}/artifacts/{name}/verify` заново считает хеши копий на сервере (`ok`, `differs`, `missing`), `DELETE` удаляет копию, `GET` показывает, что отправлено. Одна операция на сервер за раз, лимит на пользователя (`SW_ARTIFACT_RATE_LIMIT_PER_MINUTE`), при отправке файл целиком в памяти (`SW_ARTIFACT_MAX_BYTES`, 64 МиБ), действия аудита `artifact.pushed`, `artifact.verified`, `artifact.removed`, `artifact.broken`. В консоли есть страница «Артефакты» (раздел «Операции») и карточка «Артефакты» в панели сервера. Запуск артефакта это следующий срез.

## 12. Плагины-сайдкары
`community`-плагин поставляется как образ OCI с манифестом; Swellwright генерирует фрагмент `compose` (сервис `swellwright-plugin-<id>`, внутренняя сеть, `read_only`, `cap_drop: [ALL]`, лимиты, сетевая политика на разрешённые хосты) и **не получает `docker.sock`**: администратор применяет фрагмент командой `docker compose up -d`. Связь с ядром по аутентифицированному HTTP/gRPC; плагин не видит БД, Redis и чужие секреты, секрет выдаётся на время вызова.
