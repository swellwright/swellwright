# 02. Модель данных

Prisma-схема ([`packages/db`](../../../packages/db/README.md), ADR 0013) строится по этому описанию сущность за сущностью; пока реализованы `User`, `Credential`, `RecoveryCode`, `Session`, `Invitation` и `AuditEvent`. Чувствительные поля шифруются на уровне приложения (хранилище `vault`), а не только диска. Классы данных: **S** секрет (только в хранилище), **P** персональные или чувствительные (маскируются по умолчанию), **N** обычные.

## 1. Доступ и аудит
| Сущность | Поля | Класс |
|---|---|---|
| `User` | id, имя, email (опц.), роль, статус, язык, тема, последний вход | P |
| `Credential` | пароль (Argon2id), TOTP-секрет (S; запечатан ключом аутентификации экземпляра, а не хранилищем, чтобы вход работал при запечатанном хранилище, ADR 0014), ключи WebAuthn (публичные), коды восстановления (хеши; отдельная таблица `RecoveryCode`) | S |
| `Session` | id, пользователь, хеш токена, этап (`password_verified`, `active`), IP, UA, создана, последняя активность, простой и абсолютный срок, повышена до (реализовано, ADR 0017) | N |
| `Invitation` | пользователь (одно открытое приглашение на пользователя), хеш токена (токен показывается один раз), назначение (`invite`, `reset`), срок (72 часа), кто выдал (null для серверной команды; без внешнего ключа). Удаляется при использовании (ADR 0016) | S (хеш) |
| `Role` / `RolePermission` | имя, набор разрешений (`servers:write`, `runs:execute:deploy`, `terminal:use`, `vault:reveal` …). Пять встроенных ролей это фиксированные наборы в `packages/contracts` (ADR 0015); таблицы придут вместе со своими ролями | N |
| `ApiToken` (Swellwright) | имя, хеш, scopes, срок, последнее использование, IP-ограничения | S (хеш) |
| `AuditEvent` (`audit_events`) | seq, время, субъект (id и имя на тот момент, без внешнего ключа), действие, исход (`success`, `failure`, `denied`), объект, IP, id запроса, подробности (плоские, каноническая строка), хеш предыдущей записи, собственный хеш (цепочка). Только добавление: триггеры базы отказывают в изменении, удалении и очистке (ADR 0015) | N |

## 2. Хранилище секретов (vault)
| Сущность | Поля |
|---|---|
| `VaultMeta` (реализовано, ADR 0018: одна строка; параметры и соль Argon2id, KEK под ключом фразы, KEK под ключом восстановления; состояние запечатано/распечатано живёт в памяти процесса; блока проверки нет, обёртка сама подтверждает фразу) | версия KEK, параметры Argon2id, проверочный блок, состояние (запечатано/распечатано) |
| `Secret` | id, имя, тип (`panel-token`, `ssh-key`, `ssh-password`, `ssh-ca`, `dns-oauth`, `provider-token`, `telegram`, `generic`), шифртекст (AES-256-GCM), обёрнутый DEK, версия, метаданные (срок, область применения), владелец секрета, политика раскрытия |
| `SecretUse` | какой запуск или шаг использовал какой секрет (без значений) |
| `SecretRotation` | история ротации, следующая плановая дата |

## 3. Инвентарь
| Сущность | Поля |
|---|---|
| `Provider` | имя, тип драйвера (`manual`, `hetzner` …), аккаунт-секрет, ссылка на `infra-billing` панели |
| `Server` | id, имя, провайдер, IPv4/IPv6, страна, ОС, состояние жизненного цикла (`draft`, `provisioning`, `active`, `draining`, `retired`), теги, заметки, ссылка на узел панели (uuid), ключи хоста (отпечатки), способ доступа (ссылка на секрет), окно обслуживания |
| `ServerAccess` | способ (`password`, `key`, `cert`), пользователь, порт, приоритет, ограничение источника |
| `ServerFact` | JSON фактов (ОС, ядро, пакеты, службы, порты, версии, диск, время), метка времени, источник |
| `ServerSnapshot` | запуск, каталог на сервере, хеш манифеста, размер, статус (создан, использован для отката, удалён) |
| `ServerEvent` | события жизненного цикла и дрейфа |
| `NodeLink` | связь `Server` и узла Remnawave (uuid узла, профиль, инбаунды, хосты) |

**Сделано в фазе 2 (ADR 0034):** `Server`, `ServerHostKey` (закреплённые отпечатки SHA-256), `ServerAccess` и `ServerFact`. У сервера уникальное имя, адрес, порт SSH, страна, провайдер текстом, состояние, теги и заметки. Запись доступа (`password` или `key`) называет секрет хранилища подходящего вида и при желании второй секрет для `sudo`; обе ссылки запрещают удаление, так что секрет, который используется, удалить нельзя, а записей у сервера не больше пяти. Факты собираются по SSH (ADR 0037): `ServerFact` хранит типизированный документ (`schemaVersion` 1, каждое поле может быть пустым, предупреждения о том, что прочитать не удалось), время, запись доступа и SHA-256 скрипта только для чтения, который их собрал; запись доступа помнит, когда её пробовали в последний раз и удался ли вход. Провайдер как объект, окно обслуживания, связь с узлом панели, сертификаты как способ и остальные сущности этого раздела пока не сделаны.

**Сделано в фазе 2 (ADR 0038):** `Script` (имя, описание, текст, уровень опасности `read`/`change`/`destructive`, выполняется ли от root, типизированные параметры в JSON, встроенный или нет, версия, которая растёт с каждым изменением текста, SHA-256 текста; встроенные создаются и обновляются по имени при старте), `CommandRun` (режим `script` или `inline`, состояние, точный текст, что выполнялся, с хешем, имя и версия скрипта, значения параметров, уровень и подтверждённый уровень, лимит времени, кто запустил, `cancel_requested_at`; текст сохраняется при правке или удалении скрипта), `CommandRunTarget` (один сервер запуска: состояние `pending`, `running`, `succeeded`, `failed`, `lost`, `cancelled` или `skipped`, запись доступа, которая сработала, идентификатор шага, выводимый из своего id, код выхода, код и сообщение ошибки, `waiting`, времена и по каждому потоку сохранённые байты, размер, увиденный на сервере, признак `truncated` и последние 16 КиБ) и `CommandOutputChunk` (вывод сырыми байтами, один кусок на чтение, ключ: цель, поток и смещение). Строка `Script` в таблице ниже это библиотека этого среза; права на отдельный скрипт не сделаны (`servers:exec` покрывает все).

**Сделано в фазе 3 (ADR 0041):** `PanelConnection` (пока одна строка, но ничто не мешает нескольким): `baseUrl`, `tokenSecretId` (секрет хранилища вида `panel_token`; удаление запрещено, пока он используется, и хранилище называет подключение), `state` (`connected`, `degraded`, `unreachable`, `unauthorized`, `unsupported`; `unconfigured` это отсутствие строки), `panelVersion`, `capabilities` (что токен может читать, по ресурсам), `trustedCa` (публичный PEM удостоверяющего центра для этой панели), `tokenExpiresAt` (читается из поля срока действия токена), `lastCheckedAt`, `lastErrorCode` и `lastErrorMessage`, `createdById`. Самого токена в строке нет. `PanelSnapshot` и `PanelDiff` пока не сделаны; у видов объектов панели, которые снимок будет сравнивать, есть `hash` их замаскированной конфигурации.

## 4. Конфигурация и эталоны
| Сущность | Поля |
|---|---|
| `Blueprint` | шаблон развёртывания: образец профиля, режим профиля, сквады, образец хостов, лимиты, провайдер, профиль усиления, версия установщика, DNS-политика |
| `Baseline` | эталон ноды: список проверок, ожидаемые значения, версия |
| `BaselineResult` | сервер, проверка, исход, детали, время |
| `Convention` | правила имён и полей: шаблон remark, address=IP, sni явный, политика fingerprint, диапазон `vlessRoute`, маркер тестовых объектов (🧪) |
| `PanelConnection` | панель (URL, версия, возможности), токены (ссылки на секреты), срок, состояние |
| `PanelSnapshot` | типы объектов (профили, хосты, сквады, шаблоны, настройки, плагины), JSON, хеш, время, зашифровано |
| `PanelDiff` | пара снимков, различия |
| `HopChain` | вход, выход, `vlessRoute`, профиль хопа, хосты, режим (`always`, `direct-first`), состояние |

## 8. Артефакты и библиотека
| Сущность | Поля |
|---|---|
| `Artifact` | тип (`installer`, `node-engine`, `baseline`, `script`, `template`), версия, хеш SHA256, содержимое, подпись, примечание |
| `ServerArtifact` | Сделано (ADR 0039): сервер (каскадом), имя и версия артефакта из каталога, SHA-256 и размер, которые отправили, место (`user` или `system`), путь на сервере, когда и кем отправлен, последняя проверка (`ok`, `differs`, `missing`, когда, какой хеш увидели). Одна строка на сервер, имя и версию. Сам каталог это директория `artifacts/` образа, сверяемая с манифестами, а не таблица |

| `ChangeAdvisory` | записи об уязвимостях и релизах (CVE, USN, GitHub), затронутые версии, рекомендация, метка «факт/гипотеза» |

## 9. Хранение и срок жизни
- События и журналы запусков: 12 месяцев (настраивается), чанки вывода: 6 месяцев, потом сжатие.
- Результаты зондов: сырые 90 дней, агрегаты 2 года.
- Снимки панели: ежедневные 90 дней, недельные 2 года.
- Аудит: без удаления (экспорт и архив).
- Секреты: версии хранятся до отзыва; значения никогда не пишутся в журналы, события и снимки (проверка при записи).

## 10. Миграции и начальные данные
Prisma migrate, откат миграций через резервные копии. Инициализация: `bootstrap` создаёт владельца экземпляра (роль `owner`) и хранилище, затем мастер подключения панели загружает парк (импорт узлов, хостов, профилей), собирает факты по SSH и строит первый отчёт дрейфа без изменений (усыновление существующих нод, сценарий N01).
