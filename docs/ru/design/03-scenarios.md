# 03. Каталог сценариев (полный)

Каждый сценарий это «рабочий процесс» движка (`08-engine.md`) с циклом **план, согласование, применение, проверка, откат**. Для каждого: что делает, защиты, откат. Блокировки ставятся на ресурсы: нода, сервер, зона DNS, профиль панели, сервер панели. Уровни риска: Н низкий, С средний, В высокий (нужно согласование и окно обслуживания).

Условные обозначения откатов: **полный** (возврат к состоянию до запуска, кроме перечисленных исключений), **частичный** (часть шагов необратима, перечислено), **нет** (только чтение).

## A. Серверы и ноды (N)

### N01 Усыновление существующей ноды (риск Н, только чтение)
Подключение по SSH, сбор фактов, снимок-эталон «как есть», сверка с эталоном (набор проверок варианта узла и расширения), отчёт дрейфа, связь с узлом панели и записями DNS и cert-sync, оценка риска. Ничего не меняет. Результат: нода в инвентаре со статусом «усыновлена», видны расхождения и план их исправления.

### N02 Добавление сервера в инвентарь (Н)
Ввод IP, провайдера, учётных данных (пароль root нового сервера, ключ, сертификат), проверка доступности, отпечаток ключа хоста с явным подтверждением, определение ОС, архитектуры, ресурсов, `python3`. Импорт из панели («узлы без сервера»). Откат: удалить запись.

### N03 Развёртывание новой ноды (В)
Параметры: страна и номер (следующий свободный), домен по соглашению, IP, провайдер и биллинг, лимит трафика и день сброса, образец профиля, **режим размещения инбаунда** (новый отдельный профиль, добавление в общий профиль с предупреждением о рестарте всех нод профиля, клон образца), сквады, образец хостов, профиль усиления, окно обслуживания, режим DNS (вручную / через драйвер), политика входа (root, администратор, SSH-сертификат Swellwright).
Этапы: `connect` (SSH, отпечаток, ОС), `dns` (A-запись), `snapshot` (снимок сервера до изменений), `preflight` (ресурсы, интернет, порты, время), `install` (шаги установки; для схемы self-steal это шаги артефакта `node-installer` в порядке его действия `full`: `base`, `system`, `hostname`, `firewall`, `fail2ban`, `docker`, `apiacl`, `certsync`, `nginx`, `haproxy`, `node`, `verify`, параметры каждого в `manifest.json`, ADR 0036; их состав задаётся вариантом узла, node-flavor; шаги с риском потери доступа, например межсетевой экран, идут с таймером страховки), `reboot` (если нужен), `certsync_panel`, `panel` (профиль и инбаунд, ключи REALITY от панели, нода, два хоста, сквады, биллинг, метаданные узла), `online`, `verify` (набор проверок эталона, задаётся вариантом узла), `access` (установка доступа Swellwright: ключ/сертификат, администратор, проверка входа и sudo), `ssh` (запрет root и т. д. только после проверки), `cleanup`, `notify`.
Общие требования к шагам и защиты от типичных сбоев: идемпотентность, ожидание блокировки менеджера пакетов, повторы получения внешних артефактов, подробные журналы, шаги отдельным процессом на ноде; проверка уникальности тега и имени; вход администратора проверяется до запрета root (SSH не ужесточается, пока нет проверенного запасного доступа); снимок до первого изменения; повторный запуск идемпотентен.
Откат: **полный**, кроме обновлений пакетов, ядра, перезагрузки и журналов (панель по записям, DNS по записям, сервер по снимку, cert-sync-запись).

### N04 Переразвёртывание (В)
Существующая нода на новом или переустановленном сервере. Профиль и ключи REALITY сохраняются, SECRET_KEY берётся новый (`GET /api/keygen`; допущение «подходит любой ключ» проверяется в лаборатории), адреса хостов и DNS обновляются при смене IP, из `known_hosts` cert-sync удаляется старый ключ, при необходимости перезапуск ноды через панель. Варианты: тот же IP (переустановка ОС), новый IP, новый провайдер (обновляются провайдер и биллинг). Откат: **полный** по записям (адреса хостов, DNS, cert-sync, сервер).

### N05 Переименование ноды (С)
Новый код (`XX-04`), домен, режим «безопасный» (старое имя остаётся запасным: nginx `server_name`, HAProxy SNI, `serverNames` инбаунда) или «быстрый». Меняется: hostname, `/etc/hosts`, nginx, HAProxy, сохранённые параметры установщика; запись cert-sync (со старого имени на новое); DNS (новая A-запись; старая по подтверждению); в панели: имя ноды, адрес (если домен), код страны, `serverNames` инбаунда, имя профиля (если он только этой ноды), remark, `sni` и `address` хостов, метаданные, запись биллинга; тестовые хосты (помеченные по соглашению, например 🧪) не трогаются. Поиск ссылок на старое имя во всех профилях, шаблонах, хостах других нод, правилах и хопах; найденное в хоп-профилях предлагается заменить, прочее показывается списком.
Этап 2 **«финализация»**: убрать запасное имя на сервере и в `serverNames`, удалить старую A-запись; запускается вручную или по расписанию после проверки, что клиенты обновили подписки (по `subscription-request-history`).
Защиты: проверка DNS на авторитативных серверах, предупреждение о рестарте Xray на всех нодах общего профиля, возможность выбрать «клон профиля для ноды» заранее, проверка по новому SNI после изменений. Откат: **полный**.

### N06 Вывод ноды из эксплуатации (В)
Снятие нагрузки (`isDisabled` у хостов, вывод из сквадов, ожидание отключения пользователей), проверка отсутствия ссылок (хопы, шаблоны), отключение ноды, удаление ноды, хостов и инбаунда (или профиля), удаление DNS, cert-sync, записи биллинга, архивирование сервера, по желанию отзыв доступа и «очистка» сервера (стирание секретов и остановка служб), возврат сервера провайдеру (через API, если есть). Откат: до удаления ноды **полный**; после удаления «частичный» (восстановление объектов панели из снимка).

### N07 Замена заблокированной ноды (В)
Сценарий для случаев вроде узла, заблокированного на транзите: разворачивание на новом IP или сервере (N03 или N04), понижение TTL заранее, двойной режим (старая остаётся до проверки), переключение хостов, проверка из зондов, вывод старой (N06). Опционально включение хопа как запасного пути (P10).

### N08 Смена IP одного сервера (С)
Новый IP у того же сервера: DNS, хосты, при необходимости ACL порта API, правила fail2ban, обновление HAProxy `bind`, cert-sync, зонды; сценарий согласует порядок «сначала добавить, потом убрать».

### N09 Перенос между профилями, разделение и слияние (В)
Клонирование общего профиля «под ноду» (как для входного узла цепочки), перенос инбаунда, слияние обратно; расчёт влияния на рестарты; запись старого состояния для отката. Сделано в фазе 3 (ADR 0044): расчёт влияния это пробный прогон (`POST /panel/impact`), который говорит, какие ноды перезапустятся, остановятся или запустятся и почему (каждое правило помечено как наблюдалось, документировано или предположение), какие хосты и подписки изменятся, что найдёт проверка соглашений после изменения, уровень риска и, для общего профиля, более безопасный путь (клонировать его под ноду); он ничего не меняет.

### N10 Обновление образа ноды и Xray (В)
Стратегии: канарейка (одна нода), затем волнами; проверки после каждой: нода online, время Xray, пользователи online, заданные пороги; остановка при провале и откат на предыдущий тег. Источник версий: релизы node и Xray на GitHub, закрепление тега в compose и артефакте. Учёт «срочных» релизов безопасности. Откат: **полный** (предыдущий образ остаётся на диске до конца окна).

### N11 Обновление ОС, ядра, перезагрузки (В)
Политики: список затронутых пакетов, CVE-метки (`S09`), окна, канарейка, `reboot-required`, ожидание возврата, проверка (BBR, `fq`, время, службы, Xray), параллелизм 1: перезагрузка по одной ноде с защитой от потери доступа. Откат: ядро не откатывается (старое остаётся в загрузчике).

### N12 Эталон усиления: проверка, дрейф, исправление (Н/С)
Набор проверок эталона и расширения (служба, порты, UFW, DOCKER-USER, fail2ban, sshd, sysctl, сертификат, права ключа, SNI_VERIFICATION, заглушка и т. д.). Сравнение с эталоном; для расхождения предлагается **исправляющий шаг из установщика** (идемпотентный) и показывается дифф. Расписание: ежедневно «проверка», по запросу «исправление» с согласованием. Результаты хранятся, видны тренды.

**Сделано в фазе 3 (ADR 0045): половина проверки, только чтение.** Эталон это версионируемый документ из проверок поверх закрытого каталога из 31 наблюдения только на чтение (`docs/en/baselines.md`); два поставляются с Swellwright (`linux-generic`, `node-selfsteal`), ваши это копии с вашими значениями. Один скрипт, один SSH-сеанс на сервер; результаты с увиденным значением, ожиданием и подсказкой; дрейф относительно прошлого запуска; обзор парка; расписание (`SW_CHECKS_INTERVAL_HOURS`, по умолчанию выключено). Исправляющий шаг и согласование это фаза 4: подсказка называет шаг установщика, который нужно выполнить.

### N13 Порт API ноды (ACL): изменение списка разрешённых адресов (В)
Массовое изменение списка адресов, которым открыт порт API ноды (список разрешённых адресов, источников доступа к порту API; DOCKER-USER, UFW), например при смене внешнего адреса панели: канарейка, проверка, что панель видит ноду, откат. Предусмотрены несколько адресов (основной и запасной).

### N14 UFW, fail2ban, порты SSH (С/В)
Добавление и удаление разрешённых адресов, `ignoreip`, смена порта SSH через двойной режим (два порта, проверка, снятие старого), политика паролей и root; всё с таймером страховки на ноде (авто-возврат) и проверкой нового входа.

### N15 Доступ: ключи, пароли, центр сертификатов, аварийный доступ (В)
Ротация SSH-ключей администратора (добавить, проверить, удалить), ротация пароля sudo, выдача SSH-сертификатов (`TrustedUserCAKeys`), отзыв, список ключей по нодам, контроль «есть запасной вход» перед ужесточением, проверка fail2ban-бана самого Swellwright.

### N16 Сертификаты узла: проверка и распространение (С)
**Ядро:** состояние сертификата на каждой ноде (издатель, срок, права ключа, самоподписанный или нет), сроки и тревоги, сценарии «зарегистрировать ноду для получения сертификата», «синхронизировать сейчас», «забыть старый ключ хоста при переразвёртывании».
**Распространение** выполняет плагин (`CertDistributor`): `certs-rsync` (распространение по rsync), `certs-push-ssh`, а `certs-cron-script` — адаптер к внешнему скрипту синхронизации сертификатов (команда, список нод и пользователь задаются в настройках). Выпуск сертификата: `CertIssuer` (плагины `acme-*`; внешний источник выпущенных сертификатов описывается настройками плагина).
Защиты: проверка состояния до и после, возврат записи в схеме при откате, контроль прав ключа (640), предупреждение при самоподписанном сертификате. Откат: **полный** по записям.

### N17 SelfSNI, заглушка, nginx, HAProxy (С)
Версионные шаблоны конфигов (SelfSNI, сайт по умолчанию, HAProxy), содержимое страниц-заглушек (в том числе уникальные на ноду; возможное будущее расширение), применение с проверкой (`nginx -t`, `haproxy -c`), мягкое перечитывание и откат. Эталонный `curl`-набор проверок снаружи.

### N18 Docker и контейнеры (Н/С)
Ротация логов Docker, лимиты, очистка образов, дрейф compose, проверка `SNI_VERIFICATION=true`, закреплённый тег.

### N19 Системные настройки (Н/С)
sysctl (BBR, `fq`, MTU probing и др.), journald, NTP с запасными серверами, модули, лимиты.

### N20 Перезапуски и питание (С)
Перезапуск контейнера ноды, Xray через панель, служб (nginx, HAProxy, fail2ban), перезагрузка сервера, питание через API хостера.

### N21 Переустановка ОС через API хостера и автоматическое переразвёртывание (В)
Для провайдеров с API: переустановка образа, получение пароля root, затем N04. Для остальных: «ручной шаг» (администратор переустанавливает ОС у хостера и вводит IP, root, пароль).

### N22 Резервные копии конфигураций нод и восстановление (С)
Регулярный шифрованный снимок `/etc` (выбранные), каталога установки ноды и каталога сертификатов (пути задаются в настройках), списков пакетов; восстановление на новом сервере (часть N04). Хранение вне Swellwright по выбору.

### N23 Панель здоровья ноды и таймлайн (Н)
Онлайн, время Xray, пользователи, трафик, нагрузка, диск, память, ядро, версии, срок сертификата, последняя проверка и дрейф, события развёртываний, зонды; фильтры и тревоги.

### N24 Групповые операции (каркас)
Выбор нод по тегам и условиям, стратегии (последовательно, канарейка, пачки по N, максимум сбоев, пауза при сбое, окна), предварительный расчёт (какие ноды, сколько времени, влияние), согласование, единый прогресс по всем нодам, повтор для упавших.

### N25 Разовые команды и скрипты (С/В)
Библиотека скриптов (аудит, диагностика), параметры, опасность, права; запуск на выбранных нодах, вывод по нодам, `sudo` по политике, согласование для опасных. **Сделано в фазе 2 (ADR 0038):** тринадцать встроенных диагностик только для чтения и скрипты экземпляра с типизированными параметрами и уровнем опасности; скрипт или команда запускаются на одном-пятидесяти выбранных серверах, каждый сервер это отдельная цель со своим состоянием, кодом выхода и выводом (хранится до предела, читается по смещению, виден вживую); сохранённый доступ и закреплённый ключ хоста, `sudo` через сохранённый секрет sudo, лимит времени, отмена и история запусков, которая хранит точный текст, что выполнялся. Нужно разрешение `servers:exec` и свежий код аутентификатора; запуск не уровня `read` нужно подтвердить (согласования движка появятся в фазе 4).

### N26 Файлы (С)
Просмотр, загрузка и скачивание по SFTP, раздача файла на выбор нод с контрольной суммой, права, откат (резервная копия заменяемого файла).

### N27 Веб-терминал SSH (В)
Вкладки, повышенная аутентификация на сессию, запись и воспроизведение, тайм-аут простоя, баннер, список активных сессий, принудительное закрытие, раздельное право, журнал команд (по возможности), широковещательный ввод по умолчанию выключен (`05`).

### N28 Аварийные сценарии (В)
**Компрометация ноды**: изоляция (закрыть порты, отключить хосты), ротация ключей REALITY и shortId, SECRET_KEY, SSH-ключей, пересборка ноды. **Утечка токена панели, DNS или хранилища**: отзыв, выпуск новых, перезапись секретов, аудит использования. Пошаговые мастера с проверками.

## B. Панель Remnawave (P)

### P01 Подключение панели (С)
Мастер: URL, вход админа (логин/пароль, OAuth2 или passkey), **создание токенов со scopes** (`POST /api/tokens`, каталог `GET /api/tokens/scopes`), сохранение в хранилище, **выброс админского JWT**, проверка совместимости версии (`/api/system/metadata`), список возможностей, сроки токенов и напоминания о ротации. Несколько панелей.

### P02 Профили конфигураций (В)
Список, просмотр, дифф версий (Monaco), клон, правка инбаундов через конструктор (REALITY: `serverNames`, `target`, `xver`, `shortIds`, `privateKey` от `GET /api/system/tools/x25519/generate`), пресеты sniffing (`routeOnly: true`, без `fakedns`), DNS (DoH), маршрутизации (блок SMTP и др.), **линтер конфигов** (песочница с `xray -test` в контейнере), **калькулятор влияния** (какие ноды перезапустятся, сколько секунд), применение со снимком и откатом, уникальность тегов. Предупреждения по общим профилям.

### P03 Ротация REALITY-ключей и shortId (В)
Поэтапно: генерация, обновление профиля, проверка подписок и клиентов, откат. Для каждой ноды отдельно при клонированных профилях.

### P04 Хосты (С)
CRUD, клон, пакетные операции (отключить, включить, удалить, обновить), сортировка; **движок конвенций** (значения по умолчанию, настраиваются): remark по шаблону, `address` = IP, `sni` явный, политика fingerprint (по умолчанию `firefox`; допустимый набор настраивается, наблюдаемое ограничение совместимости описано в `04-remnawave-integration.md`), типы подписок, диапазон `vlessRouteId` (по умолчанию вне 0x4000-0x4FFF), пометка тестовых хостов (например 🧪) и их защита от массовых правок; **сверка хостов и нод**: дрейф адреса, SNI, привязка к инбаунду; исправление с дампом и откатом. Сделано в фазе 3 (ADR 0044): движок соглашений это набор правил как данные (30 правил, язык шаблонов, который не может работать экспоненциально долго, версии, импорт и экспорт; собственная схема установки это набор, а не код), а сверка хостов, нод и инвентаря серверов только проверяет, с DNS под тайм-аутом, потолком и ограничением частоты; исправление с дампом и откатом придёт вместе с записью в панель.

### P05 Сквады (С)
Внутренние (состав инбаундов, влияние: рестарт затронутой ноды), внешние (шаблон, заголовки, страница подписки), пользователи пакетно.

### P06 Шаблоны подписок (В)
Версии и дифф, песочница проверки целого конфига клиента, раскатка на внешние сквады и хосты с копией и откатом, типовые шаблоны (например, «выборочная маршрутизация» и «глобальный режим») с раздельным DNS, опциональные параметры локальной аутентификации клиента из хранилища; матрица совместимости с клиентами (Happ и др.) заполняется администратором.

### P07 Настройки подписок и правила SRR (С)
`GET/PATCH /api/subscription-settings`: заголовки (`providerid`, `socks-auth-mode`, `http-auth-mode`), тестер правил (`POST /api/system/testers/srr-matcher`), раскатка.

### P08 Страницы подписок (Н/С)
`subscription-page-configs`: список, клон, порядок, привязка.

### P09 Пользователи (опционально, Н/С)
CRUD, пакетные действия (продлить, сбросить трафик, обновить сквады, отключить), HWID-устройства, «подозрения в шаринге», история запросов подписки, соединения (сброс, geocheck), тестовые пользователи для зондов (создание и автоудаление), маскирование персональных данных по умолчанию.

### P10 Цепочки хопов (В)
Мастер: вход (например, входной узел) и выход (выходной узел), профиль хопа (аутбаунд VLESS+REALITY на выход, fingerprint, параметры из инбаунда выхода), `vlessRoute` (выдача свободного; по умолчанию вне 0x4000-0x4FFF и не 0), хосты хопа (по умолчанию два режима, например «выборочная маршрутизация» и «глобальный режим»), служебный пользователь и служебные сквады (по умолчанию защищены от удаления и отключения), проверка конца в конец через зонд (внешний IP выхода), контроль по умолчанию (настраивается): **не включать Torrent Blocker** на выходе и в цепочке без анализа (источник трафика = IP предыдущей ноды), удаление цепочки без остатков. Многозвенные цепочки (A, B, C). Топология отображается графом.
**Режим «прямой путь с резервом через хоп»** (экспериментальный, зависит от поддержки клиентом): балансировщик и наблюдатель Xray, `injectHosts`, `fallbackTag`, проверка поддержки клиентом; запасной вариант «два хоста с выбором».

### P11 Плагины, сниппеты, интеграции узлов (С)
Torrent Blocker (отчёты, статистика, очистка), общие списки, плагины, исполнитель, сниппеты, интеграции: список, привязка к нодам, предупреждения для цепочек.

### P12 Биллинг инфраструктуры (Н/С)
Провайдеры, записи по нодам, история платежей; синхронизация с инвентарём (провайдер, срок оплаты, напоминания), отчёты по стоимости.

### P13 Узлы в панели (С/В)
CRUD узлов, теги, включить/выключить, перезапуск, сброс трафика, порядок, пакетные изменения профиля (`bulk-actions/profile-modification`), метаданные узла (связь с сервером Swellwright); **опасные** операции (`DELETE`, `restart-all`, массовые) требуют повышенного согласования.

### P14 Настройки Remnawave (В)
Просмотр и правка `remnawave-settings` (OAuth2, passkeys, Telegram, брендинг) с предупреждениями; по умолчанию только чтение.

### P15 Токены API панели (В)
Каталог scopes, создание токенов с наименьшими правами (для Swellwright, MCP, зондов, отчётов), срок и напоминания, отзыв; требуется админский JWT (поток повышенной аутентификации).

### P16 Версии и обновление панели (В)
Совместимость, источники релизов (панель, node, Xray, subscription-page), рекомендации по безопасности, планировщик обновлений: резервная копия, `docker compose pull`, миграции, проверка, откат из резервной копии; порядок «панель, потом ноды» с проверкой совместимости `node` и `backend`.

### P17 Резервные копии панели (С)
Расписание, шифрование (CMS, ключ вне сервера), хранение на сервере и во внешнем хранилище (S3, SFTP, rclone-цели), срок хранения, **ежемесячная проверка восстановления** в одноразовом Postgres, мастер восстановления (защита от случайного запуска), список секретов для сохранения при переустановке.

### P18 Снимки конфигурации панели (GitOps) (С)
Ежедневный экспорт всех объектов (профили, хосты, сквады, шаблоны, настройки, плагины, биллинг) с маскированием секретов или шифрованием, дифф и «кто и когда менял» (по журналу Swellwright), восстановление одного объекта, экспорт в YAML (по желанию в Git).

### P19 Статистика и отчёты (Н)
Трафик по нодам и сквадам, использование, recap и digest, Prometheus, сводки.

### P20 Аудит панели (Н)
Автоматические проверки: версии, порт 62050 только для панели, `SNI_VERIFICATION`, ядро и CVE, BBR, лимиты логов, SSH-политики, рассинхрон конвенций; отчёт в формате Markdown и в интерфейсе.

### P21 Консоль API (С/В)
Типизированный обозреватель всех 218 операций (спецификация OpenAPI Remnawave 3.4.x) с подстановкой схем, историей, «сухим прогоном» (проверка тела по контракту), для записи требуется согласование; опасные (`DELETE`, массовые) помечены. **Сделано в фазе 3 (ADR 0046), половина на чтение:** каталог, типизированные параметры, замаскированный ответ и история; запись и сухой прогон это фаза 7.

## C. DNS (D)
- **D01 Драйверы:** RU-CENTER (NIC.RU) (OAuth по паролю, обмен XML, commit/rollback, ожидание на авторитативных NS), Cloudflare, Route 53, Яндекс Cloud DNS, Selectel, Reg.ru, Timeweb, RFC 2136 (nsupdate), «вручную».
- **D02 Записи:** желаемое и фактическое состояние, создание, замена, удаление, откат, конфликты (CNAME, несколько A), история изменений, видимость на каждом NS и у рекурсивного резолвера, импорт зоны.
- **D03 Стратегия TTL:** понижение перед миграцией, повышение после.
- **D04 Соглашение об именах:** `{cc}{n}.{база}`, пул нейтральных доменов для SNI (возможное будущее расширение), проверка зон и wildcard.
- **D05 DNS-переключение (опционально):** временный перевод имени на другой IP при блокировке; по умолчанию выключено.

## D. Безопасность и доступ (S)
- **S01 Хранилище секретов:** запечатывание, распечатывание паролем, ротация KEK и DEK, аварийный экспорт, «кто использовал секрет».
- **S02 Вход:** локальные пользователи, TOTP, WebAuthn (passkey), OIDC (опц.), политика сессий, IP-ограничения, повышенная аутентификация для опасного.
- **S03 Роли и токены Swellwright:** владелец экземпляра (`owner`), оператор (`operator`), наблюдатель (`observer`), терминал (`terminal`), аудитор (`auditor`); scopes токенов.
- **S04 Центр SSH-сертификатов:** выпуск короткоживущих сертификатов, раздача `TrustedUserCAKeys`, отзыв (`RevokedKeys`), аварийный ключ вне Swellwright.
- **S05 Аудит:** неизменяемый журнал с цепочкой хешей, экспорт, поиск.
- **S06 Редактирование секретов в выводе** и сканирование журналов на утечки.
- **S07 Цепочка поставок:** замороженные зависимости, SBOM, сканирование образов, проверка лицензий, проверка стороннего кода перед подключением.
- **S08 Отчёты соответствия:** сводка по нодам и панели, история.
- **S09 Каналы уязвимостей:** USN Ubuntu, GitHub advisories (Remnawave, Xray, ядро), сопоставление с версиями нод, срочные уведомления и готовые планы (например временная мера для CVE ядра).
- **S10 Мастера инцидентов** (см. N28).

## E. Мониторинг и зонды (O)
- **O01 Агенты-зонды** на машинах в других сетях: TCP-подключение, TLS-рукопожатие с SNI, запрос через VLESS (тестовый пользователь, `xray`), тест заморозки (отправка 16-20 КБ), ICMP, `mtr -T`; режимы «прямой» и «через туннель»; фиксация пути (внешний IP).
- **O02 Расписания и матрица:** нода на оператор на время суток; график суточной картины доступности (периодическая недоступность в определённые часы суток), сравнение с эталоном, наложение событий развёртывания.
- **O03 Алерты:** правила (доля сбоев, блок узла на транзите, расхождение внешнего адреса панели со списком разрешённых адресов порта API ноды, срок сертификата, срок токена, дрейф), подавление «дребезга», окна обслуживания, эскалация.
- **O04 Метрики нод:** опрос по SSH (лёгкий) и метрики панели (`/api/system/nodes/metrics`), опциональный Prometheus-экспортёр.
- **O05 Уведомления:** Telegram первым (плагин `notify-telegram`: бот, список разрешённых чатов, тревоги, итоги запусков, ожидающие согласования с кнопками «одобрить/отклонить» для низкого и среднего риска; высокий риск только в интерфейсе), затем вебхук и почта; сводки дня и недели, тихие часы.
- **O06 Рекомендации** (с согласованием, не автодействие): заменить IP, включить хоп, временно отключить хост, перекатить на другой профиль; помечаются «измерено / предположение».
- **O07 Журнал инцидентов:** начало, причина, действия, длительность.
- **O08 SLO:** доступность по нодам и операторам.

## F. Платформа (X)
- **X01 CLI `sw`:** все запуски и чтение из терминала.

- **X03 Вебхуки наружу:** события запусков, алертов (подпись HMAC).
- **X04 Импорт и экспорт:** шаблоны, конвенции, эталоны, расписания в YAML.
- **X05 Расписания** и окна обслуживания.
- **X06 Отчёты** (HTML/Markdown/PDF): аудит, парк, стоимость, инциденты.
- **X07 Локализация:** ru и en.
- **X08 Резервные копии Swellwright** и самовосстановление.
- **X09 Обновления Swellwright** (проверка релизов, миграции, откат).
- **X10 Драйверы-плагины** для хостеров и DNS (подключаемые).
- **X11 Мастер первого запуска** (создание владельца экземпляра, хранилище, панель, усыновление парка).
- **X12 Каталог справки** («факт / гипотеза»), встроенная справочная документация.
- **X13 Агент на ноде (опц., позже):** исходящее соединение, для серверов без SSH.
- **X14 Мультипанельность.**
