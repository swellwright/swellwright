# apps/api

For the complete implemented scope through phase 3, see [current project status](../../docs/en/project-status.md).
The notes below introduce the foundation; they are not an exhaustive list of today's API modules.

NestJS API: controllers, gateways, authentication, OpenAPI (phase 1).

Status: first slice. `GET /api/v1/health`, `/ready`, `/version` and `/openapi.json`, request ids, one error envelope, contract-checked responses. First-run setup, password plus authenticator sign-in, sessions and sign-out (`/setup/*`, `/auth/*`, [ADR 0014](../../docs/adr/0014-sign-in-with-password-and-authenticator.md)). Permissions per route, `/roles`, and the audit chain with `/audit` and `/audit/verify-chain` ([ADR 0015](../../docs/adr/0015-permissions-and-the-audit-chain.md)). Users, invitations and credential reset (`/users`, `/auth/invitations/accept`, `/auth/password`, [ADR 0016](../../docs/adr/0016-users-invitations-and-credential-reset.md)), and a command for the host when nobody can sign in: `pnpm --filter @swellwright/api admin -- users` and `... admin -- reset-credentials <login name>` (in a built image: `node dist/admin.js`, with the environment of the server). Step-up authentication: a signed-in session is elevated by the sign-in and renewed with `POST /auth/step-up`; routes that declare `stepUp` answer 403 `step_up_required` otherwise ([ADR 0017](../../docs/adr/0017-step-up-authentication.md), `SW_STEP_UP_MINUTES`). The secrets vault (`/vault/*`, `/secrets`, [ADR 0018](../../docs/adr/0018-the-vault-key-hierarchy-and-its-first-slice.md), `SW_VAULT_KDF_MEMORY_MIB`, `SW_VAULT_KDF_PASSES`): sealed on every start, unsealed in the console. Tests that need a database run one file at a time against a server that cannot run transactions of several processes side by side (`node --test --test-concurrency=1`). `/ready` checks Postgres (the migrations of `packages/db` must be applied) and Valkey when their URLs are set. Run it with `pnpm --filter @swellwright/api start` (see `.env.example`); design in `docs/en/`.
